# Governance

Toskar Core is maintained by YEIXIO LLC.

Maintainers decide what is merged and what is released. Community proposals are welcome as GitHub issues and in [GitHub Discussions](https://github.com/yeixio/toskar-core/discussions). A useful proposal states the problem, who it is for, and whether it changes the HTTP API or the node protocol.

Major architectural changes should start as an issue or a discussion before a large pull request. That includes new runtimes, changes to pairing, and changes to placement.

Contribution does not grant maintainer status on its own. Maintainer status is an explicit decision by the current maintainers. The ladder below says what each role can do and what the maintainers look for before they invite someone to it.

## Roles

| Role | What you can do | How you get there |
| --- | --- | --- |
| **Contributor** | Open issues, discussions, and pull requests. | Anyone, from the first report or pull request. |
| **Triager** | Label, assign, and close issues and discussions. Ask for reproductions. Mark issues `good first issue`. | Three merged pull requests, or a steady record of useful reports and answers, plus an invitation from a maintainer. |
| **Reviewer** | Approve pull requests in one area, such as runtimes, hardware, the web UI, translations, or docs. A maintainer still merges. | Regular, careful contributions to that area over a few months, plus an invitation. |
| **Maintainer** | Merge, cut releases, and decide the roadmap with the other maintainers. | Invited by the current maintainers after time as a reviewer. |

Current people in each role are listed in [MAINTAINERS.md](MAINTAINERS.md). A maintainer who invites someone opens a pull request that adds them there.

Roles are about trust, not volume. Small, focused pull requests with tests, clear reports, and helping other people in issues and discussions all count. Nobody needs to ask for a role: the maintainers review the contributor list each release and reach out.

Someone who has been inactive for six months moves to an emeritus list in MAINTAINERS.md and can return by asking. Anyone who breaks the [Code of Conduct](CODE_OF_CONDUCT.md) can lose a role.

Contributions are covered by the [Toskar Contributor License Agreement](CLA.md). See [CONTRIBUTING.md](CONTRIBUTING.md) before sending code.

Day-to-day discussion should stay in this repository. Discussion categories:

- General
- Ideas
- Hardware & Runtimes
- Show and Tell
- Help
